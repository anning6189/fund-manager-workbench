# 消费行研 Agent 正确性、性能与输出结构修补 v2.1

版本：2.1.0  
实施日期：2026-08-13  
适用范围：消费行业研究、公司比较、行情复盘、公告与研报扫描；继续禁止基金持仓、仓位和组合暴露推断。

## 1. 本轮修补结果

盲测暴露的四类正确性问题已进入机器准入门：

1. 行情日期必须与请求日或请求区间逐条一致；错年、越界记录隔离并只允许缩小分片重试一次。
2. 数值标准化必须保留原值、原单位、换算因子、标准值和标准单位；跨来源差异超过20%进入冲突检查，10倍、100倍等数量级错误单独识别。
3. 企业风险必须绑定法定主体标识、集团关系、案件角色和重大性；仅名称相似不得进入上市公司核心风险结论。
4. 核心事实必须有稳定原文URL或文档ID及定位；缺原文的研报只作为第三方观点，缺原文的公告摘要只作为回源线索。

## 2. 新的回答算法

旧流程的主要问题是：先串行查完所有来源，再统一核验和写答案；宽查询发生过量返回后还会原样重试；年报PDF和宏观数据没有充分利用缓存；研报、新闻和企业风险超时会拖住核心答案。

v2 改为“证据优先的并行有向无环图”：

### P0：规划与缓存，预算3秒

- 解析实体、证券代码、截止时点、指标、期间和输出模板。
- 生成精确缓存键和小分片查询；先读取实体树、年报页级摘录、历史财务和宏观发布缓存。
- 禁止无界搜索和未过滤回退。

### P1：核心数据并发，预算35秒

- 两家公司财务按“每家公司一个请求”并发；每次最多6个指标、2个期间。
- 行情一次请求所有比较证券的完整区间，并额外取得N日前基线收盘价。
- 公告按发行人拆分并发；每次最多3种文档类型、100天窗口。
- 国家统计局等官方宏观序列直接查询或读取发布缓存。

### P2：验证和冲突回源，预算20秒

- 先执行日期、单位、实体、会计口径和证据定位校验。
- 只有缓存缺失、关键字段缺失或来源发生重大冲突时，才下载／读取官方PDF对应页面。
- 官方A级来源优先；冲突记录进入隔离区，不参与答案。

### P3：补充信息并发，预算22秒

- 研报和企业风险按公司分片并发，每家公司最多3篇研报、4类风险事件。
- 补充来源超时不阻塞核心答案；系统记录缺口并继续。
- 新闻只用于发现线索，政策和公司事实必须回到官方原文。

### P4：渐进式合成，预算10秒

- 先输出已验证的核心答案：结论、财务、行情、重要公告和证据缺口。
- 研报观点和风险复核完成后再补充；不得为等待非关键来源延迟核心结果。
- 达到时间预算时输出“已验证的部分答案+缺口”，禁止用未经验证内容补齐版面。

### P4 输出结构锁定

- 固定采用“研究口径—执行摘要—行业判断—横向比较看板—公司深挖—行情与事件—风险反证—结论与跟踪—证据索引”的正文顺序。
- 相同维度的两家公司数据集中在一张横向表中，禁止退化成公司 A、公司 B 两段重复数字清单。
- 行业事实、Agent 推断和机构观点分层展示；运行耗时和工具状态不进入研究正文。
- 测试运行信息仅在用户要求时作为最后一个附录输出，并区分“调用有返回”和“所需字段完整”。
- 详细版式见 `docs/fund-manager-research-output-template-v2.1.md`。

## 3. 缓存策略

- 年报页级摘录、历史财务：一年TTL，内容哈希或更正稿触发失效。
- 官方宏观发布：30天TTL，修订版本触发失效。
- 已完成的日行情：交易所最终确认后视为不可变，30天TTL。
- 公告索引：6小时TTL，从上次发布日期增量更新。
- 研报元数据：7天TTL；在许可允许时保存原文定位。
- 企业风险：24小时TTL；“无风险命中”只负缓存6小时。
- 所有缓存读写同样经过许可和历史时点门，不能用当前缓存污染历史研究。

## 4. 重试、超时和停止规则

- 最大重试1次；原样重复宽查询被禁止。
- 只对超时、429、502、503、截断、日期错位和必需指标缺失重试。
- 重试必须把分片减半，或切换官方来源。
- 研报、新闻和非重大企业风险属于非关键路径，超时即记录缺口。
- 关键事实证据完整，且新增来源不太可能改变实质结论时立即停止搜索。

## 5. 性能验收

基于阶段五已经记录的真实连接器延迟，使用确定性关键路径模型：

- 旧串行模型：129.80秒。
- v2核心答案模型：26.20秒。
- v2完整答案模型：44.65秒。
- 相对串行改善：65.6%。

以上是用历史实测延迟建模的结果，不伪装成一次新的端到端在线压测。生产目标为：缓存命中核心答案45秒内、冷启动核心答案65秒内、冷启动完整答案90秒内、硬截止120秒。

## 6. 自动验收

运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\Test-ResearchRuntimeV2.ps1
```

验收覆盖：

- 正常记录通过；
- 2026查询错回2025行情被阻断；
- 名创收入放大10倍被识别为数量级冲突并隔离；
- 仅名称匹配的企业风险被阻断；
- 缺原文的研报降级为非阻塞第三方观点；
- 两家公司财务请求按实体拆分并行；
- 补充任务不进入核心关键路径；
- 基金经理版输出顺序不可回退，运行附录必须置于正文之后；
- 延迟模型改善不低于50%，完整答案模型不超过90秒。

## 7. 仍然存在的外部边界

- Gildata 的合同、内部展示、缓存和再分发许可仍需要基金公司法务／采购确认。
- 行情、研报和企业风险的实际并发上限应按供应商配额调优；当前策略使用全局6、单供应商4、单域名2。
- 缺少稳定原文链接的研报只能作为观点，不能承担关键事实证据。
- 估值、渠道动销、同店、售罄率和市场份额数据仍需继续接入，才能形成完整投决支持。
