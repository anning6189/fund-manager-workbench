# 阶段三：消费行业分类与对象模型 v1.1

> 2026-08-12 修补说明：73 个细分类均已从文本名称升级为稳定编码节点；增加分类版本政策和实体分类赋值 schema。机器规格以 `specs/consumer-domain-model.v1.json` 为准。

状态：设计完成，待数据连接器导入全量实体  
适用对象：公募基金经理消费行业研究 Agent  
边界：不包含基金持仓、组合暴露、调仓或交易对象

## 1. 设计目标

本模型为全部消费研究数据提供共同语言，使不同来源中的公司、证券、品牌、品类、产品、渠道、区域、客群和消费场景能够被稳定识别、关联和按历史时点还原。

阶段三完成的是分类标准、数据模型、统一 ID、消歧和版本规则；不宣称已经导入全市场公司、品牌或 SKU 全量数据。

## 2. 分类原则

1. 内部投研分类为主，外部标准通过映射表保留，不把任何单一外部分类当作全部消费研究边界。
2. 公司设置一个有时间效力的主分类，可同时拥有多个次分类和收入暴露。
3. 公司、证券、品牌、品类和 SKU 分开建模；品牌不等于公司，证券不等于法人实体。
4. 行业归属、品牌所有权、渠道关系和产品状态均使用有效期，支持历史回溯。
5. 原始来源值不得覆盖；标准化结果与来源记录并存。
6. 不确定映射必须保留置信度和人工审核状态。

## 3. 内部全消费分类树

顶层代码 `CR`，下设三个消费组、十一个一级板块。二级节点详见 `specs/consumer-domain-model.v1.json`。

### CR.S — 必选与高频消费

- `CR.S.FB` 食品饮料：白酒、啤酒及其他酒、软饮与包装水、乳品、休闲食品、调味品、速冻预制与餐饮供应链、烘焙、肉制品、保健营养食品。
- `CR.S.PH` 美容个护与家庭护理：护肤、彩妆、香水、洗护、口腔护理、个护用品、家清及纸品。
- `CR.S.PT` 宠物与家庭新消费：宠物食品用品、宠物医疗服务、母婴用品、玩具潮玩及其他家庭新消费。

### CR.D — 可选与耐用消费

- `CR.D.AP` 家电与消费电子：白电、厨电、黑电、小家电、清洁电器、智能家居和消费电子终端。
- `CR.D.AU` 汽车与出行消费：乘用车、摩托车、汽车流通、售后服务及出行消费服务。
- `CR.D.HL` 家居与生活空间：成品家具、定制家居、软体家居、家装、家居建材及家居流通。
- `CR.D.AF` 纺织服饰与运动户外：服装、鞋履、运动户外、家纺、珠宝首饰及可穿戴消费品。

### CR.V — 消费渠道与服务

- `CR.V.RT` 商贸零售与电商：商超、百货、专业连锁、免税、电商平台、即时零售及零售服务。
- `CR.V.FS` 餐饮与本地生活：正餐、快餐、茶饮咖啡、烘焙门店、餐饮供应链及本地生活平台。
- `CR.V.TL` 酒店旅游与休闲服务：酒店、景区、旅行社/OTA、博彩与主题公园、体育健身及休闲服务。
- `CR.V.CE` 文化娱乐与教育消费：游戏、影视院线、音乐阅读、线上娱乐、非学历教育及其他文化消费。

### 边界处理

- 医药制造和医疗器械默认不属于本消费分类；医美服务、药店零售、健康管理等面向消费者的服务可作为跨域节点挂接。
- 农林牧渔、化工、包装等默认作为消费产业链上游，不自动成为消费公司；若公司主要收入来自消费品牌或终端业务，再按收入暴露分类。
- 互联网平台、消费电子和汽车等跨传统行业对象采用主分类加多标签，不重复创建公司实体。
- 烟草制品保留外部分类映射和产业链关系，不默认纳入可投资消费公司池。

## 4. 多轴分类

除主行业外，每个研究对象可以拥有以下独立维度：

- 必选/可选/服务消费组
- 产业链角色：原料、制造、品牌、经销、平台、零售、服务终端
- 商业模式：直营、经销、加盟、平台、会员、订阅、授权、制造代工
- 渠道：线下直营、经销、商超、专卖、电商、直播、即时零售、团购等
- 地域：全球、国家、省市、城市等级、商圈
- 客群：年龄、收入、家庭阶段、用途和其他合规分群
- 场景：居家、宴席、商务、出行、旅游、运动、送礼、健康等
- 价格带：只在指定品类、区域、币种和有效期内定义
- 生命周期：导入、成长、成熟、衰退；必须记录判断日期和证据

## 5. 核心实体

- `classification_node`：内部或外部分类节点。
- `legal_entity`：依法设立的公司或组织。
- `issuer`：承担证券发行和披露义务的主体。
- `security`：股票或其他证券；交易所代码是属性，不是永久主键。
- `brand`：面向市场的品牌，可跨公司、品类和区域。
- `product_category`：产品或服务类别。
- `product_sku`：具体产品/SKU；在无法取得全量数据时允许只建产品系列。
- `channel`：销售与触达渠道。
- `geography`：国家、行政区、城市等级或研究区域。
- `customer_segment`：合法合规的消费者分群。
- `consumption_scene`：购买或使用场景。
- `price_band`：品类、地域、币种和日期限定的价格区间。
- `value_chain_node`：产业链环节。
- `entity_alias`：名称、简称、历史名称、英文名和供应商别名。
- `external_identifier`：统一社会信用代码、LEI、ISIN、交易所代码、供应商ID等。
- `relationship`：实体间有方向、有类型、有时间、有来源的关系。
- `source_record`：保留来源原值和采集元数据的不可变记录。

## 6. 关系模型

必须支持的关系包括：

- 法人 `OWNS/CONTROLS` 品牌或其他法人
- 发行人 `ISSUES` 证券
- 品牌 `HAS_PRODUCT` 产品/SKU
- 产品 `BELONGS_TO` 品类
- 公司/品牌 `OPERATES_IN` 行业、渠道、地域和场景
- 公司 `PARTICIPATES_IN` 产业链环节
- 公司/品牌/产品 `HAS_EXPOSURE_TO` 子行业、地域、渠道或客群，并可附收入/销量占比
- 分类节点 `MAPS_TO` 外部标准节点
- 实体 `SUCCESSOR_OF/MERGED_INTO/RENAMED_FROM` 历史实体

所有关系至少保存 `valid_from`、`valid_to`、`observed_at`、`source_id`、`confidence` 和 `review_status`。

## 7. 统一 ID

- 永久实体ID格式：`cr:<entity_type>:<ULID>`，不编码行业、名称或交易所等可变信息。
- 分类节点代码：`CR.<group>.<sector>.<subsector>`，版本由分类方案字段单独管理。
- 外部ID单独存储，并带类型、签发机构、有效期和是否主标识。
- 合并实体不删除：旧ID标记 `merged` 并指向保留ID，历史引用仍可解析。
- 同一公司不同上市证券必须是不同 `security`；同一品牌在不同国家使用不同名称时仍可关联同一品牌或建区域子品牌。

## 8. 实体匹配与消歧

匹配优先顺序：

1. 法定唯一标识精确匹配：统一社会信用代码、LEI、ISIN等。
2. 交易所 + 证券代码 + 有效期匹配。
3. 规范化法定名称 + 注册地匹配。
4. 品牌/产品名称 + 所有者 + 品类 + 区域联合匹配。
5. 模糊名称只产生候选，不自动合并。

自动合并阈值建议不低于0.98；0.85—0.98进入人工审核；低于0.85保持独立。唯一标识冲突一律阻断自动合并。

## 9. 版本与时间

模型同时记录：

- `valid_time`：现实世界中关系或属性何时有效。
- `system_time`：系统何时知道、写入或修订该事实。
- `published_at`：来源何时发布。
- `as_of_date`：数据描述的业务时点。

历史研究必须按照当时可得信息重建，禁止用后来修订的行业归属、品牌所有权或证券代码覆盖历史状态。

## 10. 阶段三验收结果

- 已定义覆盖全消费的内部分类树和边界规则。
- 已定义多轴分类、核心实体、关系、ID、别名、消歧、版本和历史规则。
- 已定义与 GB/T 4754—2017、JR/T 0020—2024、居民消费支出分类及市场化行业分类的映射接口。
- 已提供机器可读 JSON Schema 风格规格和种子分类。
- 未完成项明确为：依赖阶段五连接器导入并审核全量公司、品牌、产品和SKU主数据。

## 11. 依据

- GB/T 4754—2017《国民经济行业分类》，国家统计局归口，现行有效。
- JR/T 0020—2024《上市公司行业统计分类与代码》，对标国民经济行业分类并适用于资本市场统计。
- 国家统计局《居民消费支出分类（2013）》，提供食品烟酒、衣着、居住、生活用品及服务、交通通信、教育文化娱乐、医疗保健、其他用品和服务等消费目的分类。
