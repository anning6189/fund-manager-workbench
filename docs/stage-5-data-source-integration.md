# 阶段五：数据源正式接入

版本：1.0.0  
验收日期：2026-08-12  
适用范围：面向公募基金经理的全消费行业研究 Agent；不接入基金持仓、组合暴露或仓位推断。

## 1. 验收结论

阶段五的核心数据接入层验收通过，判定为：`accept_core_data_access_layer_with_declared_external_gates`。

这里的“完成”有严格边界：

- 20 个具体来源进入统一注册表，覆盖 18 个来源家族；
- Gildata MCP 的 7 项能力均已真实调用成功，并保存了延迟、样例与语义风险；
- 13 个政府、交易所和法定披露来源均找到可用的程序访问路径；
- 巨潮资讯官方年报完成下载、大小检查、SHA-256、文档 ID 和证据定位闭环；
- 所有来源统一受许可、历史时点、实体/指标/期间白名单、证据和质量准入门控制；
- 渠道零售、行业协会、另类数据三类商业来源尚未采购，保持“已登记、未接入”；
- Gildata 的合同与再分发条款尚未核验，因此当前处于许可闸门后，只允许连接测试和内部技术验证。

因此，本阶段不是宣称“市场上所有数据已经购买完毕”，而是完成了可运行、可审计、不会掩盖授权缺口的数据接入底座。

## 2. 已正式接入的来源

### 2.1 Gildata MCP：7 项实时能力

1. `FinQuery`：公司基本资料、财务报表、行情、估值和证券属性；
2. `AnnouncementData`：公告与定期报告检索；
3. `MacroIndustryData`：宏观与行业时序；
4. `FinancialResearchReport`：券商研报检索；
5. `NewsDataQuery`：新闻、舆情与政策线索；
6. `IcEnterpriseDataQuery`：工商、许可、处罚、司法和企业信用；
7. `SmartStockSelection`：A 股证券池、行业分类与市场筛选。

七项能力的传输测试均成功，但没有一项可以把服务端原始返回直接送给 Agent：所有能力都观察到不同程度的过量召回、额外字段或低精度问题。因此生产链路强制执行客户端精确过滤、字段投影、去重、截断检查和官方主源交叉校验。

### 2.2 官方来源：13 个可用访问路径

- 法定披露与交易所：巨潮资讯、深交所、上交所、北交所；
- 统计与贸易：国家统计局、海关总署、商务部；
- 产业与政策：工信部、中国政府网、国家发改委、市场监管总局；
- 金融与服务消费：中国人民银行、文化和旅游部。

其中 11 个入口通过只读 `HEAD` 返回 HTTP 200；海关入口拒绝 `HEAD`，但只读 `GET` 返回 HTTP 200；国家统计局交互查询页对当前程序请求返回 403，已采用官方数据发布页 HTTP 200 的替代路径，并要求与授权结构化源的官方来源字段交叉验证。

## 3. 已落地的生产组件

### 3.1 来源治理

- `source-registry.v1.json`：来源身份、覆盖、更新频率、许可、访问等级、时点能力、适配器、质量闸门与探针状态；
- 许可优先级：官方主源 > 授权结构化数据库 > 授权研报库 > 可信公开信息 > 未核验信号；
- 冲突策略：官方原始发布优先；实质冲突未解决时并列展示并阻断确定性结论。

### 3.2 统一连接器契约

所有 MCP、网页、PDF、统计数据和政策文件进入同一请求/响应模型，并执行 13 步流水线：密钥认证、请求拆分、超时调用、原始元数据捕获、无猜测解析、实体/指标/时间/单位标准化、许可门、历史时点门、范围白名单、去重、证据绑定、研究输入验证和审计日志。

### 3.3 官方文档抓取器

`Get-OfficialDocument.ps1` 已实现：

- 仅允许 HTTPS；
- 按来源执行精确域名白名单；
- DNS 解析后阻断环回、内网、链路本地、CGNAT 和组播地址；
- 检查跳转后的最终域名；
- 单文档上限 50 MB；
- 保存内容类型、字节数和 SHA-256；
- 生成统一文档对象、证据等级、许可标签、版本和审计元数据；
- 失败时清理未完成文件。

巨潮资讯的美的集团 2023 年年度报告完成实测：6,617,110 字节，SHA-256 为 `22f4915d91ada74a37eab8d074aef4c15420f3b1a8b5f5bd5777c00f97d58b86`，定位为 PDF 第 9、160、162 页。

### 3.4 数据分层

- `raw`：原始响应和原始文档，仅用于追溯；
- `normalized`：实体、指标、时间、单位和文档标准化；
- `curated`：通过许可、时点、证据和质量门，可供研究 Agent 使用；
- `quarantine`：许可不明、实体未消歧、口径冲突、未来信息或证据不可定位的数据。

## 4. 数据质量与合规边界

### 必须阻断

- 认证失败或许可不明；
- 响应截断且拆分重试后仍不完整；
- 使用截止时点之后才公开的信息；
- 实体、指标或财务报表口径无法唯一确定；
- 关键事实缺少证据定位、版本或内容哈希；
- 实质来源冲突尚未解决；
- 请求或结果涉及基金持仓、组合暴露或仓位推断。

### 只作线索

- 新闻和舆情默认只作为信号；
- 研报观点必须标明作者观点，不能代替官方事实；
- 企业风险库中的重大事项需与官方工商、监管或司法来源复核；
- 结构化财务值需与法定披露交叉校验。

## 5. 未接入项与外部动作

以下三类不是技术故障，而是基金公司需要决定是否采购及如何合规使用：

1. 家电、电商、渠道库存和终端零售等商业数据；
2. 汽车、家电、酒业、连锁、酒店旅游等行业协会的非统一接口数据；
3. 消费者面板、门店客流、位置、支付和 App 行为等另类数据。

此外，基金公司的法务/采购需要确认 Gildata 的 API 使用范围、内部展示、缓存期限、研报摘录和再分发条款。在确认前，系统会继续保留许可闸门。

## 7. 阶段五后的系统能力

现在 Agent 已经具备从多来源查询信息、识别来源层级、限制查询范围、过滤服务端过量返回、保存历史可得时间、绑定可定位证据并阻断不合格数据的基础能力。下一阶段可以在此之上建设知识库、实体解析、文档解析/切片、指标时序仓库和增量更新任务，而无需重新设计数据准入规则。
