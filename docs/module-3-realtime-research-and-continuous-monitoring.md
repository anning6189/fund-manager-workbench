# 模块三：实时研究与持续监控

## 已实现

- 事件驱动、定时扫描和系统健康三类监控模式。
- 行情、公告、财报、政策、宏观、行业数据、新闻线索、企业风险、数据质量和来源新鲜度十类事件合同。
- 事件时间、系统可得时间、检测时间和研究截止时间四重时间控制，阻断未来信息。
- 数据新鲜度、研究覆盖缺口、许可闸门、研究工作流积压和重大研究事件五类默认规则。
- 告警去重、出现次数、状态机、内部订阅、投递箱、人工确认和运行审计。
- 重大事件自动匹配研究模板，但仅形成 `suggested` 任务；不自动执行、不自动发布。
- 每次运行生成 JSON 与 Markdown 内部研究简报。

## 首轮真实状态扫描

截至 `2026-08-12T23:59:59+08:00`，系统评估了 54 个信号，生成 54 条内部告警和 22 条研究任务建议。22 条数据流中，新鲜 0 条、过期 1 条、未启动 21 条。因此监控运行状态为 `partially_complete`，而不是伪称实时数据已经齐备。

Gildata 资讯检索已用于验证实时事件入口；检索结果因许可、精确定位和原始来源复核要求，仅作为 `raw_license_gate` 后的新闻线索，不直接成为正式研究结论。

## 安全边界

- 所有告警默认 `internal_only`。
- 所有投递都留在内部 outbox，不自动向外部人员发送消息。
- Agent 不能代替命名研究员确认告警。
- 不使用或推断基金持仓、仓位。
- 不自动产生买卖指令。
- 正式报告仍需阶段八的人类发布闸门。

## 持续调度

已在当前 Codex 任务中登记“消费行业每日研究监控”，每天北京时间 08:30 运行。周期任务只汇报新增、升级或需要人工处理的内部研究事项；没有变化时仅给出简要状态。
