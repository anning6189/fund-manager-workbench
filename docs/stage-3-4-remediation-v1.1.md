# 阶段三、四问题修补说明 v1.1

修补日期：2026-08-12  
目标：关闭冒烟测试中的两个 P0 和六个 P1 问题，并建立可重复执行的生产准入门。

## 修补结果

1. 73 个细分类全部获得稳定编码，代码唯一且含状态、层级、有效期。
2. 64 个专业指标全部具备定义、类型、公式、单位、频率、粒度、时间语义、首选证据等级、可比性、缺失处理和校验规则。
3. 公共指标由 31 项扩充为 35 项，新增营业成本、销售费用、经营活动现金流量净额和归母净利润，补齐公司比较计算链的原始输入指标。
4. 5 个 P0 模板全部具备机器可读的输入字段、输出字段、证据要求和验证规则。
5. 历史时点从日期升级为带 UTC 偏移的 `cutoff_timestamp`，并定义 `exact_timestamp`、`end_of_day`、`market_open`、`market_close` 四种可用性模式。
6. 连接器响应强制记录查询 ID、抓取时间、原始记录数和截断标记；截断时硬阻断并拆分重试。
7. 实现实体、证券、指标、期间、报表类型、历史时点和证据完整性七层确定性过滤。
8. 证据对象要求 `available_at`、文档版本、SHA-256 内容哈希、许可标签及可定位位置。
9. 财务观测必须声明报表类型、合并范围、会计准则、币种、单位比例、重述状态和期间类型。
10. 公司比较默认只能按维度给有限结论；没有明确决策规则、权重和时间周期时，禁止输出单一赢家。

## Gildata 适配

新增 Gildata 金融研究适配契约，明确：

- 每次最多两家公司、八个指标、两个期间，结果过多或截断时自动拆分；
- 营业收入不能与营业总收入互换；
- 公司/证券、指标、期间和报表类型只能做精确白名单匹配；
- 无法确认合并范围、发布时间、证据定位或许可状态时，禁止进入正式答案；
- MCP token 只能保存在运行时密钥系统，不得进入仓库、证据对象或日志。

## 自动化准入门

`tools/Test-ResearchInput.ps1` 对连接器规范化输出执行以下检查：

- 查询与响应契约；
- 历史截止时点；
- 证据完整性、哈希、许可和定位；
- 实体、证券、指标、期间与报表类型白名单；
- 财务报表口径字段；
- 计算输入和复算结果；
- 公司比较结论边界。

`tools/Test-Stage34Regression.ps1` 包含八个回归场景：规格完整性、合格历史用例、未来信息穿越、截断响应、无规则单一赢家、越界实体、错误计算和不可定位证据。

## 回归结果

- 规格版本：领域模型 v1.1.0、指标字典 v1.1.0、证据标准 v1.1.0。
- 11 个赛道、73 个细分类稳定编码。
- 35 个公共指标、64 个专业指标，机器字段完整率 100%。
- 5 个 P0 模板 schema 完整率 100%。
- 八项回归测试全部通过。
- 有效美的—格力用例：采用两份巨潮资讯官方年报，记录精确财务报表页码及完整 PDF SHA-256；2 条证据、12 条原始观测、8 条计算通过，0 错误、0 警告。
- 未来材料测试：成功以 `future_information_leakage` 硬阻断。

## 当前边界

本次完成的是规格、适配契约和本地确定性准入器。Gildata MCP 本身的服务器端行为无法由本地代码改变，因此过量召回、字段缺失和截断通过适配层过滤、分片与阻断处理。真实公司主数据、第三方接口字段绑定和文档页码解析仍会在后续连接器与知识库建设中持续扩充，但已经不能绕过本次准入门。
