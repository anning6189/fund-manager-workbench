# 阶段八：研究工作流与 Agent 编排

## 1. 阶段结论

阶段八已完成。此前阶段形成的研究证据规范、数据源路由、阶段六时点事实库与阶段七模型引擎，现在被编排成一条可执行、可恢复、可审计、生成后直接展示的消费行业研究工作流。

本阶段没有重新定义项目，也没有把研究范围收窄为单一消费子行业。当前美的集团与格力电器案例只是用于验收通用编排能力的测试请求；同一工作流契约可承载整个消费行业中的行业扫描、公司比较、事件研究和专题研究。

系统不使用、不请求且不推断任何基金持仓或仓位，不自动生成交易指令。

## 2. 编排角色

工作流定义了 9 个职责相互分离的 Agent 角色：

1. 研究总控 Agent：规范研究任务、固定截止时点、形成 DAG、决定阻断或降级。
2. 实体与口径 Agent：消歧公司、证券与品牌，统一期间、币种、报表和行业口径。
3. 事实与证据 Agent：从阶段六事实库读取点时事实和来源文档。
4. 模型 Agent：按需调用阶段七模型并保留公式、输入和情景血缘。
5. 研究结论 Agent：区分事实、计算和推断，形成逐结论证据图。
6. 证据审核 Agent：检查截止时点、直接证据、计算血缘和反方证据。
7. 反方审查 Agent：提出替代解释、不可下结论事项和证伪指标。
8. 报告交付 Agent：按基金经理阅读结构生成报告与证据索引。
9. 合规闸门 Agent：阻断持仓字段、仓位推断、自动交易指令和自动外部发布，并确认系统质量门状态。

## 3. 工作流 DAG

10 个任务分为 8 个执行波次：

```text
范围闸门
  -> 实体与口径解析
  -> [点时事实检索 || 来源文档检索]
  -> 模型执行（可降级）
  -> 逐结论图生成
  -> [证据审核 || 反方审查]
  -> 基金经理报告生成
  -> 合规检查并直接展示
```

方括号中的任务在同一波次并行。事实、结论、报告、合规属于必需任务，失败会阻断；标记为非必需的模型包失败会被记录为降级，不会让有充分事实证据的报告全部失败。

## 4. 已实现的运行能力

- 任务请求校验：固定工作流、读者、研究截止时间、实体、指标、模型包边界。
- 绝对时点查询：带不同时区偏移的时间戳按绝对时间比较，避免把截止前信息误判为未来信息。
- DAG 计划与并行波次：验证依赖不存在缺失或环路，同一波次最多并发四个独立任务。
- 状态机：`planned -> running -> completed`，异常可进入 `blocked` 或 `failed`。
- 中断续跑：已完成任务不会重复运行，保存的请求、输出与任务状态可用于恢复。
- 幂等：相同 `package_id + package_hash` 返回原运行；同一 ID 内容变化会被阻断。
- 失败隔离：必需任务失败阻断，非必需模型任务失败降级并显式披露。
- 直接展示：全部必需系统质量门通过后写入 `internal_research_ready` 并立即出现在基金经理工作台。
- 审计链：每个任务的角色、波次、依赖、尝试次数、起止时间、输出、异常和状态变更均入库。

## 5. 逐结论质量控制

工作流不会只在报告末尾堆放来源，而是为每条结论保存独立结构：

- `FACT_PRIMARY` 必须链接直接证据。
- `AGENT_CALCULATION` 必须保存公式、输入 observation ID 和支持证据。
- `AGENT_INFERENCE` 必须与事实及计算区分。
- 重大有限结论必须包含反方证据或反方分析。
- 任何证据的可用时间晚于研究截止时间即阻断。
- 数据缺口必须显式输出，不能用猜测补全。

## 6. 交付物

每次工作流运行生成五类产物：

- `execution-plan.json`：角色、DAG、执行波次和质量闸门。
- `claim-graph.json`：事实、计算、推断、公式、输入和逐结论证据关系。
- `evidence-audit.json`：时点、直接证据、计算血缘及反方证据审核结果。
- `research-report.md`：基金经理文字报告，包含同口径比较、有限结论、反方解释、后续跟踪和证据索引。
- `runtime-audit.json`：完整任务运行、恢复、降级、异常和直接交付日志。

数据库迁移 `sql/003_consumer_research_workflow_engine.sql` 新增工作流定义、请求包、运行、任务、结论、结论证据、产物、复核和事件九类审计表。

## 7. 使用方法

初始化：

```powershell
$env:CODEX_PYTHON = "<python.exe 的完整路径>"
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\Initialize-Stage8WorkflowEngine.ps1
```

运行研究请求：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\Invoke-Stage8ResearchWorkflow.ps1 `
  -Request .\tests\fixtures\stage8-research-workflow-request.v1.json
```

中断恢复：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\Invoke-Stage8ResearchWorkflow.ps1 `
  -ResumeRunId "wr:<run-id>"
```

也可以直接调用 Python CLI 的 `init`、`validate`、`plan`、`run`、`resume` 和 `status` 命令。

## 9. 当前边界

阶段八完成的是通用研究任务的编排和质量控制，不代表所有消费行业实时数据已经齐备。报告可以清楚区分“本次已取得的事实”“模型假设”“数据缺口”和“不可下结论事项”。正式研究使用时，阶段五已授权连接器仍需持续向阶段六事实库更新股票、公告、政府统计、政策文件、研报元数据和其他消费研究数据。
